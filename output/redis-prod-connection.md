## Client configuration

### Environment variables

```
REDIS_CLUSTER_ENABLED=true
REDIS_CLUSTER_NODES=10.50.200.91:6379,10.50.200.92:6379,10.50.200.93:6379,10.50.200.94:6379,10.50.200.95:6379,10.50.200.96:6379
REDIS_USERNAME=
REDIS_PASSWORD=<ask DevOps>
REDIS_TLS=false
```

Keep username, password and TLS as settings even when empty, so production only changes values, not code.

## Things to know when coding against it

- **The client must reach all nodes on 6379.** Clients get redirected (`MOVED`/`ASK`) to whichever node owns a key's slot.
- **Multi-key commands need a shared hash tag.** `MGET`, `MSET`, transactions and Lua scripts only work when all keys are in one slot: `{user:42}:profile`, `{user:42}:cart`. Otherwise you get `CROSSSLOT`.
- **Memory is small and nothing is evicted.** 2.50 GB per master, so writes fail with `OOM` when a shard is full. Set TTLs on cache keys.
- **Plan for a few seconds of failover.** Node timeout is 5 s. Enable topology refresh and retry on connection errors.
- **This is PRODUCTION.** Data is persisted (RDB + AOF) and replicated, but it is not a backup; keep a system of record elsewhere.
