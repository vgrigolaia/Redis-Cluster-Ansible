Redis PROD Cluster Access

Client configuration

All examples read the password from the REDIS_PASSWORD environment variable.

REDIS_CLUSTER_ENABLED=true
REDIS_CLUSTER_NODES=10.50.200.91:6379,10.50.200.92:6379,10.50.200.93:6379,10.50.200.94:6379,10.50.200.95:6379,10.50.200.96:6379
REDIS_USERNAME=
REDIS_PASSWORD=<from your secret store>
REDIS_TLS=false

Keep username, password and TLS as settings even when they are empty, so switching environments only changes values, not code.

Things to know when coding against it

  • The client must reach all 6 nodes on 6379.Clients get redirected (MOVED/ASK) to whichever node owns a key's slot, so every node has to be reachable, not just one seed.
  • Multi-key commands need a shared hash tag.MGET, MSET, transactions, Lua scripts and SUNION-style commands only work when all keys are in one slot. Put the common part in braces: {user:42}:profile, {user:42}:cart. Otherwise you get a CROSSSLOT error.
  • Nothing is evicted.With 2560 MB per master and noeviction, writes fail with an OOM error when a shard is full. Set TTLs on cache keys.
  • Plan for a few seconds of failover.Node timeout is 5 s, so a replica takes over a few seconds after its master fails. Enable topology refresh (see the Spring Boot and Lettuce examples) and retry on connection errors.
  • Modules are loaded.Vector sets, TimeSeries, JSON, Bloom, Search (Query Engine). Check their cluster behaviour in DEV before relying on them in production.
Production rules

Keep the password in a secret store and inject it at runtime; never put it in code, images or logs. Don't run KEYS, FLUSHALL/FLUSHDB, load tests or debugging sessions here; use DEV for that. Data is persisted (RDB + AOF) and replicated, but it is not a backup, so keep your system of record elsewhere. Config changes go through DevOps.
